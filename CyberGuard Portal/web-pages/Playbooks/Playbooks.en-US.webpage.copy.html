Playbooks

Step-by-step checklists for the incidents we see most. Tick steps off as you go; ticks are saved in this browser only.

EscalationReport incident
P1Ransomware or attacker moving between systemsEncryption started, shadow copies deleted, or an implant found0 of 6 done

Use the network isolation action in the EDR console. It stops SMB, WMI and WinRM traffic but keeps the sensor connected.

Collect a memory image of the host (EDR live response or your forensic tool) before you end injected processes such as rundll32, dllhost or powershell.

Turning it off destroys the memory evidence needed for keys and attribution.

Check the backup stores were not touched, then make them read-only.

Add the attacker addresses, domains and file hashes to the watchlist, then to the firewall and EDR block lists.

Call the hotline, brief the CISO and open a P1 bridge. Follow the escalation page for client and legal notices.

P2Email account taken overHijacked Microsoft 365 account, unknown forwarding rules0 of 6 done

Do this first, so the attacker cannot simply sign in again.

Update-MgUser -UserId user@client.example -AccountEnabled:$false

Revoke all sessions and refresh tokens.

Revoke-MgUserSignInSession -UserId user@client.example

Save the list as evidence first. Remove only rules the user did not create, by name.

Get-InboxRule -Mailbox user@client.example | Format-List Name,Identity,ForwardTo,RedirectTo,DeleteMessage

Remove apps you don’t recognise and note the attacker’s IP addresses for the watchlist.

Only after the steps above are done.

Treat any recent change of bank details as suspect until confirmed by phone.

P2Suspicious sign-inImpossible travel, repeated MFA prompts, or a risky sign-in alert0 of 5 done

Use a known number, not one from the alert or an email. Ask if they signed in and approved the MFA prompt.

Disable sign-in, then revoke sessions.

Update-MgUser -UserId user@client.example -AccountEnabled:$false

Review mailbox, SharePoint and admin activity from the suspicious IP address.

Then re-enable the account.

Set it to Monitor, or Block if it is clearly hostile.

P3Phishing email reportedLink clicked, attachment opened or password entered0 of 5 done

Ask for the .eml or .msg file. Forwarding strips the headers we need.

Create the search, run it, check the results, then soft-delete all copies.

New-ComplianceSearch -Name PhishPurge -ExchangeLocation All -ContentMatchQuery 'from:bad@example.com' Start-ComplianceSearch -Identity PhishPurge New-ComplianceSearchAction -SearchName PhishPurge -Purge -PurgeType SoftDelete

Add them to the watchlist and to email security.

Use click traces and sign-in logs. Treat anyone who clicked as possibly compromised.

If anyone typed their password, follow the email account playbook.

P3Malware found on a deviceEDR detection, blocked or not0 of 5 done

If it ran, isolate the device straight away.

Keep the sample and its hash for the watchlist.

Email, download, USB or another device. Check the parent process.

Search all devices in the EDR console.

Reimage if the malware had admin rights or persistence.

P3Lost or stolen deviceLaptop, phone or tablet with company data0 of 5 done

When and where it was lost, whether it was encrypted and locked.

Use device management (Intune or similar).

So tokens cached on the device stop working.

Revoke-MgUserSignInSession -UserId user@client.example

If the device was not encrypted, follow the data leak playbook.

Ask the user to report theft and send the number.

P2Data leakData sent to the wrong person, exposed online, or copied out0 of 5 done

Recall the email, remove the public link, block the destination.

Which data, how many people, whether it is personal or sensitive data.

Save logs, messages and file versions before anything is deleted.

Personal data: Commissioner within 72 hours. See the escalation page.

Use the client notice template on the escalation page.

P1Public-facing system exploitedA critical vulnerability is being used against an internet-facing system0 of 5 done

Check whether the affected version is running and reachable from the internet.

If no patch exists, apply the vendor workaround or block access at the firewall.

Web shells, new accounts, unusual outbound connections since the vulnerability was published.

Add scanning and exploit source addresses to the watchlist.

Treat any confirmed compromise as P1.
